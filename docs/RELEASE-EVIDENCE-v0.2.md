## Evidence rules

A release blocker may move to passed only when the repository points to reproducible evidence. Failed release-matrix attempts remain in the denominator. Deterministic provider fixtures and protocol stubs must never be relabeled as live-provider certification. Live provider receipts must identify the exact candidate SHA, provider kind, exact model and safe endpoint, while excluding raw credentials and raw model/page context. Machine accessibility evidence is sufficient for the current V02-B05 acceptance contract; manual AT review can be added later without blocking this release scope. Previous-stable browser coverage must prove the actual observed Chrome major/version rather than relying only on the download filename. Chrome Web Store preparation artifacts do not prove submission or approval. Do not call v0.2 complete while this document says `NOT READY FOR v0.2 RELEASE`.

When the final release candidate is ready, record the exact candidate commit, workflow run IDs, browser versions, provider/model versions, scenario results, machine accessibility evidence, package artifact hashes, Chrome Web Store item/submission/review status, and public disclosure URLs here before tagging or public submission.
